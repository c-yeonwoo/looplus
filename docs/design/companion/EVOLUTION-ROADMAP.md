# Looplus 캐릭터 세계관 · 진화 로드맵

2026-10-25. 구현과 제안을 구분한다. 아래 세계관·진화 형태는 다음 디자인 검토안이며 출시 기능으로 홍보하지 않는다.

루의 3단계 모습, 새 친구 모아·토리, 독서·스트레칭 키포즈를 [세계관과 캐릭터 시안](WORLD-AND-CHARACTERS-v1.md)으로 구체화했다. 이미지와 프롬프트는 `concepts-v1/`에 있다. 아직 형태 승인 및 실제 애니메이션 제작 전이다.

## 제품 안에서의 역할

루플러스의 친구는 사용자가 돌봐야 하는 또 하나의 할 일이 아니다. 나와 함께 일상을 배우며, 내가 남긴 실천을 취향·소품·모습으로 기억한다. 전투력이나 다른 사람보다 높은 레벨이 아니라 **내 생활을 닮아가는 성장**이 핵심이다. 기존 게임 캐릭터의 외형·이름·진화 계보를 모사하지 않는다.

## 확정된 첫 구현

- 라인: 코랄 생활 친구 ‘루’ 하나. 이름은 변경 가능한 개발상 명칭이다.
- 첫 실제 실천: 함께 시작한 기억. 독서한 서로 다른 4일: 첫 책. 연속일 조건 없음.
- hello / together / first-book은 코드의 현재 성장 상태이며, 외형이 진화하는 3종 캐릭터를 뜻하지 않는다.
- 정지 포즈: 인사 / 책 읽기 / 첫 책 축하. 새 성장에만 380ms 진입 연출. 운동 모션·프레임 애니메이션은 아직 없다.
- 보상은 기록과 함께 저장되는 안정된 ID의 원장이다. 수정·취소로 회수하지 않고 재기록으로 중복 지급하지 않는다.
- 실제 실천량·실천일 수는 현재 기록에서 다시 계산한다. 소품을 유지하려고 실제량을 부풀리지 않는다.
- 과거 기록이 있는 사용자는 다음 양수 기록 저장 때 기존 기록까지 포함해 자격을 확인한다.

## 제안 세계관: 일상을 배우는 친구들

친구들은 처음에는 자기 취향이 뚜렷하지 않다. 사용자와 책을 읽고, 움직이고, 쉬고, 정리하면서 좋아하는 일을 알아간다. 행동의 흔적은 소품에, 더 긴 시간의 변화는 실루엣과 생활 공간에 남는다.

‘진화’는 내부 개념으로 유지하고 사용자 용어는 `새로운 모습`을 우선 검토한다. 진화 전 모습도 언제든 다시 선택할 수 있어야 한다. 외형 선택을 성장 기록 초기화와 연결하지 않는다.

### 분리할 네 축

| 축 | 의미 | 설계 원칙 |
|---|---|---|
| 캐릭터 라인 | 기본 실루엣·표정·성격 | 같은 보상 규칙을 공유하고 루틴 성과의 우열을 만들지 않음 |
| 성장 단계 | 함께한 경험에 따른 외형 변화 | 새 모습 획득은 유지, 휴식으로 퇴화하지 않음 |
| 취향·소품 | 독서·움직임·정리 등 경험의 흔적 | 여러 취향 공존, 특정 분야 선택이 다른 분야를 잠그지 않음 |
| 행동·모션 | 지금 실행/기록한 루틴에 대한 반응 | 실제 수행을 감지한 것처럼 말하지 않음; 사용자의 명시적 시작·완료에만 반응 |

### 형태 발전안 — 아직 미확정

처음 만난 모습 → 생활의 취향을 발견한 모습 → 나만의 리듬이 생긴 모습.
독서·활동·돌봄 등은 우열 없는 표현 분기다. 한 분야의 시간 총량으로 분기를 고정하지 말고,
실천한 날과 여러 경험을 중심으로 자격을 검토한 뒤 **사용자가 원하는 모습**을 고르게 한다.
혼합 습관과 휴식이 불이익이 되지 않는지 사용성 검증 후 수치 조건을 확정한다.

## 자산 계약

현재 `CharacterLine → stage → activity → CharacterPose` 레지스트리와 `Character` 렌더러를 사용한다.
데이터에는 이미지 URL 대신 안정된 character/reward ID만 저장한다. 알 수 없는 ID는 보존하고,
현재 클라이언트에서 자산이 없으면 해당 단계의 기본 정지 포즈, 마지막으로 첫 인사 포즈로 폴백한다.

애니메이션 도입 시 다음 항목을 자산 manifest에 추가한다. 현재 렌더러가 이 규격을 재생한다고 주장하지 않는다.

- 라인 ID / 자산 버전 / 성장 단계 / 행동 키(idle, reading, exercise, celebrate 등).
- 정지 포스터, 캔버스·발 기준점·안전 여백, 재생 길이, 반복 정책, 파일 용량.
- reduced-motion용 정지 포스터와 정지·일시정지 동작. 백그라운드 앱에서 재생 중단.
- 생성 프롬프트·원본·제작 이력·권리 고지, 해상도와 알파 확인.
- 캐릭터별 모든 행동이 제작되지 않아도 기본 포즈가 정상 표시되는 호환 테스트.

소량의 래스터 포즈/프레임 또는 리깅 기반 런타임을 동일 장면으로 비교한 뒤 포맷을 선정한다.
웹뿐 아니라 iOS·Android에서 투명도·메모리·저사양 프레임 유지·배터리 영향을 비교해야 한다.
Lottie/Rive를 도입한다면 래스터를 자동 변환한 것을 리깅 자산으로 간주하지 않는다.

## 다음 진행 순서와 완료 조건

1. **세계관·실루엣 승인**: 루의 새 모습 2단계와 별도 라인 2개를 같은 크기로 비교. 축소해도 구별되고 유치한 육아/전투 인상이 없는지 확인. 이 단계에서 사용자에게 형태와 명명 승인받기.
2. **한 캐릭터의 행동 세트**: 인사·독서·스트레칭·걷기·축하 5개. 하나를 끝까지 제작해 독서 시작/기록 후 전환, 재생 중단, reduced-motion, 에셋 로딩 실패를 검증. 새 라인 양산보다 먼저 품질 기준을 고정.
3. **새 모습 획득·선택**: 자격 계산, 영구 해금, 사용자 선택, 옛 모습 복귀, 여러 기기 병합을 설계·구현. 보상 ID/룰 버전 변경 시 기존 소품 보존 테스트 필수.
4. **여러 라인과 친구 챌린지**: 라인 선택/교체 및 소규모 공동 경험을 연결. 개인 건강·시간 조건 비교나 공개 순위는 기본값으로 만들지 않음. 개인 기록 공개 범위는 명시적 동의.

금지: 결석으로 아픈 표정/배고픔/퇴화, 과도한 분량 입력으로 성장 가속, 유료 회복·연속기록 복구, 미제작 모션 버튼 노출, 보상 때문에 실제 목표 성과를 달성으로 자동 판정.

## 출시 전 검증

여러 시간대·일자 경계, 과거 수정/삭제, 두 기기의 동시 획득, 이전 앱 버전과의 공존, 계정 전환/초기화,
이미지 실패·오프라인·저사양 기기, 화면 읽기·큰 글자·동작 줄이기를 별도로 검증한다.
현재 클라이언트 원장은 금전 가치가 없으며 서버 권위의 부정행위 방지 시스템이 아니다.
